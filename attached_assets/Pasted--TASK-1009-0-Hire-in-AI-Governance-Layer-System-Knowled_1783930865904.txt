# TASK #1009-0

## Hire’in AI Governance Layer — System Knowledge Assimilation and Baseline Confirmation

## 1. Purpose

Before beginning the formal AI Governance Layer audit, build an accurate and concise understanding of the existing Hire’in platform.

This phase exists to prevent the audit from starting with incorrect assumptions about missing integrations, automations, workflows, access controls or system capabilities.

The task must establish:

* What the platform was designed to do
* What relevant documentation currently exists
* What the current code appears to implement
* Where documentation and code align
* Which earlier assumptions were incorrect
* Which capabilities appear reusable
* Which questions require formal verification during Wave 1

This is a knowledge-assimilation and baseline-confirmation task only.

Do not implement, repair or refactor anything.

# 3. CEO-approved operating baseline

Treat the following as approved system intent unless current authoritative documentation clearly contradicts it.

1. Simranjeet Sidana is the CEO, System Design Authority and final gate approver.

2. CEIPAL is the operational source of truth for staffing execution across Healthcare, IT and other staffing domains.

3. Hire’in is the source of truth for:

   * Employee governance
   * Goals
   * Weekly check-ins
   * Training
   * Probation
   * PIP
   * SOPs and policies
   * Attendance
   * Leave
   * Payroll
   * Manager actions
   * Employee concerns
   * Escalations
   * Audit findings
   * CEO decisions

4. Existing CEIPAL integration should be extended where needed rather than replaced.

5. Immediate managers remain responsible for employee check-ins, feedback, guidance, coaching and blocker resolution.

6. The system must audit managers as well as employees.

7. The CEO should receive material exceptions, trends and decision requests—not routine operational noise.

8. Existing notifications, schedulers, integrations and workflow automations should be reused where reliable.

9. A notification being sent is not proof that the required action was completed.

10. Missing acknowledgement, action completion or closure must be treated as a system-control gap until verified.

11. Restricted employee PII, payroll information, medical information, complaint or investigation records, authentication data and security secrets must never be sent to an external AI provider.

12. AI may summarize, classify, question, correlate and recommend.

13. Consequential employment, compensation, payroll, legal, contractual and financial decisions remain human-controlled.

14. Technical debt should be repaired with the relevant vertical implementation slice unless it is a shared critical blocker.

# 5. Evidence model

Use the following three-way comparison:

```text
Documented intent
versus
Implemented code
versus
Runtime or test evidence
```

Documentation defines intended behavior.

Code shows what appears to have been implemented.

Runtime wiring, logs and tests provide stronger operational evidence.

Do not treat:

* A work order
* A prompt
* A database table
* A route name
* A UI page
* An unused service
* An unregistered scheduler

as proof that the full capability is operational.

# 8. Baseline claims requiring confirmation

The following claims were identified during preliminary discussion.

Confirm, narrow or correct them.

## 8.1 CEIPAL integration

Possible current capabilities:

* JWT authentication
* Token refresh
* Paginated job synchronization
* Candidate search
* Applicant push
* Resume attachment handling
* Deduplication
* Error recovery
* Graceful fallback

Possible future extensions:

* Submission pipeline synchronization
* Interview stages
* Offer disposition
* Placement and start status
* Falloff status
* Client feedback
* Pipeline aging

Use precise classifications.

Do not describe the CEIPAL integration as “fully implemented” unless the supported operational scope is explicitly stated.

Preferred form:

> Active for jobs and selected candidate or applicant operations; likely reusable with extension for complete staffing-pipeline governance.

## 8.2 Scheduler

Possible scheduled functions include:

* Salary reporting
* Salary approval reminders
* Leave accrual
* Night-shift consent alerts
* Absence sweeps
* Attendance reports
* Attendance safety nets
* Manager attendance reminders
* Deadline expiration and escalation
* Content Studio reminders
* Campaign digests
* Weekly digests
* Regularization reminders
* Plan check-in reminders

Safe scheduler verification means:

1. Confirm the job definition exists.
2. Confirm the scheduler is registered from the application entry point.
3. Confirm relevant feature-flag or environment conditions.
4. Confirm timezone configuration.
5. Inspect available recent execution logs or audit records.
6. Inspect failure handling and retry behavior.
7. Inspect idempotency or duplicate-run protections where present.

Do not manually trigger cron jobs.

## 8.3 Notification gateway

Possible current foundation:

* Central `notifyUser()` function
* User-level channel preferences
* Multi-channel delivery
* Safe failure handling

Confirm:

* Which active modules use the gateway
* Whether any modules bypass it
* Whether delivery outcomes are recorded
* Whether acknowledgement is tracked
* Whether the required action is linked
* Whether escalation is linked
* Whether closure is recorded

## 8.4 Access-control foundation

Possible current foundation:

* Central `ACCESS_REGISTRY`
* `resolveRoles()` or equivalent role-resolution logic

Confirm:

* Whether major backend routes use it
* Whether legacy routes use separate logic
* Whether access is enforced only by role or also by employee hierarchy
* Whether direct-report filtering is applied
* Whether skip-level and department access exist
* Whether HR, Super Admin and CEO overrides are controlled
* Which claims require deeper Wave 1 tracing

* `CAPABILITY_SUPERSEDED`
* `POSSIBLE_GAP_REQUIRES_AUDIT`

1. Relevant documentation was reviewed.
2. Relevant terminology and aliases were searched.
3. Relevant code paths were searched.
4. Related services, routes or modules were inspected.
5. The absence is supported by evidence.
