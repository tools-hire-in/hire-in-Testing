Your SOP playbook already says training should be role-based, not overwhelming, launched in waves, acknowledged only after training, and supported by live work samples where certification is needed. That means the app must understand training depth, not just training assignment.

The correct model is:

Recommended resolver
function resolveTrainingGroups(user) {
  const groups = new Set<string>();

  groups.add("ALL");

  // RBAC-based groups
  if (user.role === "super_admin") groups.add("CEO-SuperAdmin");
  if (user.role === "manager") groups.add("Managers-All");
  if (user.role === "recruiter") groups.add("TA-Recruiter");
  if (user.role === "hr" || user.role === "operations") groups.add("Ops-HR");

  // Department-based groups
  const dept = normalize(user.department);

  if (dept.includes("healthcare")) groups.add("Healthcare-Team");
  if (dept.includes("it")) groups.add("IT-Team");
  if (dept.includes("engineering") || dept.includes("professional")) {
    groups.add("Engineering-Prof-Services-Team");
  }
  if (dept.includes("sales") || dept.includes("account")) groups.add("Sales-AM");
  if (dept.includes("business development") || dept.includes("bd")) groups.add("BD-Team");
  if (dept.includes("marketing") || dept.includes("content")) groups.add("Marketing-Team");
  if (dept.includes("finance") || dept.includes("billing") || dept.includes("payroll")) {
    groups.add("Finance-Team");
  }
  if (dept.includes("hr") || dept.includes("operations") || dept.includes("ops")) {
    groups.add("Ops-HR");
  }

  return [...groups];
}

4. Wave activation logic

Current flat assignment logic should be replaced with level-aware wave activation.

Correct wave activation flow
1. Admin activates SOP wave.
2. System finds SOPs in that wave.
3. System finds active employees/users.
4. For each user, system resolves training groups.
5. For each SOP, system checks matching sop_role_assignments.
6. System selects the heaviest matching assignment level.
7. System creates track_assignment with level snapshot.
8. System applies quiz/pass/evidence rules based on level.
9. System creates level-aware goals and check-ins.
10. System sends notifications.
11. System audit logs assignment creation.
Idempotency rule

Do not create duplicate assignments.

Use a uniqueness rule like:

UNIQUE(user_id, sop_code, training_id, sop_version)

If the wave is activated twice, the system should skip existing assignments or update only if the SOP version changed.
