## Cross-Cutting Product Rule

The BD Agent operates as a governed Virtual CBDO Copilot.

It may analyze, recommend, explain, draft, label, and warn.

It must not approve its own claims, treat team research as verified, automatically reject opportunities, commit commercial terms, invent competitor facts, use prohibited content externally, or automatically send materials.

## Manual Governance During Development and Scale

Proof-point governance, client positioning, opportunity decisions, and external communication remain human-controlled.

Use existing feature permissions. Do not create a new Knowledge Owner role in the MVP. HR access alone does not grant sales-claim approval authority.

- API and UI changes;

## Stop Conditions

Stop and report instead of improvising when:
- the live repository conflicts materially with the proposed model;
- a role-enum migration appears necessary;
- an existing system may be duplicated;
- source provenance cannot be preserved;
- a destructive migration would be required;
- an unsupported claim would need to be approved;
- a second auth, database, API client, AI provider, storage, or audit system would be introduced.
