# START HERE — Deploying Your Hire'in Content AI (No Code Needed)

You have five files plus a tracker. Together they replace the entire 7-work-order build for content creation purposes:

1. **HIREIN_MASTER_PROMPT.md** — the "secret sauce": how the AI thinks, the workflow, the guardrails
2. **HIREIN_AI_KNOWLEDGE_BASE.md** — brand, audiences, pillars, platform rules, validation
3. **HIREIN_DOMAIN_EXPERTISE.md** — staffing-industry vocabulary and mechanics so content reads like an operator wrote it, not a generalist
4. **HIREIN_PROOF_LIBRARY.md** — ⚠️ the only file with blanks. It contains a 13-question extraction interview; the answers become the proof cards that stop the AI from flagging [NEEDS_PROOF] on everything.
5. **HIREIN_PERFORMANCE_TRACKER.xlsx** — the system's memory. Content Log + Baseline & Goals + Monthly Review tabs, with an example row showing the format.

---

## ⛔ THE LAUNCH GATE — no content prompts until all four boxes are checked

The single highest-risk failure mode is going live with an empty Proof Library: the AI will correctly flag most capability claims, and the team will wrongly conclude the system doesn't work. So treat the extraction interview as a project, not a suggestion:

- [ ] **Named owner:** ______________ owns the Proof Library
- [ ] **Calendar date:** extraction interview with the delivery lead booked for ______
- [ ] **10-card minimum:** at least ten real proof cards exist (no EXAMPLE cards, every card has a source and approver)
- [ ] **Success numbers chosen:** the Baseline & Goals tab of the tracker names your three metrics (see below) with an owner per metric

Only then does anyone type the first `full package:` prompt.

## Define success BEFORE the first piece publishes

Without a baseline, the monthly review is a feelings check. Track exactly three numbers (already scaffolded in the tracker's Baseline & Goals tab):

1. **Applications** attributable to content
2. **Employer inquiries / hiring conversations** from content
3. **One engagement signal that matters per audience:** Instagram saves for H2/I2, meaningful LinkedIn comments for H1/I1

Days 1–30: just measure — that's your baseline. Then set 60- and 90-day targets from the baseline, not from hope. Impressions, likes, and follower counts are context, never success.

## Setup (after the gate is cleared)

**Option A — Claude Project (recommended)**
1. Create a Project called "Hire'in Content AI"
2. Paste the Master Prompt into the Project's custom instructions
3. Upload the Knowledge Base, Domain Expertise, and filled-in Proof Library as Project files
4. Every chat in that project is now your content creator

**Option B — Custom GPT / any other tool:** same idea — Master Prompt = instructions, the other files = knowledge.

## How to use it daily

- Heard a real question from a candidate or client? `full package: A nurse asked me "how do I know if a travel contract is legit?"`
- Strategy only: `plan: credentialing delays for OR nurses`
- Check an existing draft: `validate` + paste it
- **[NEEDS_PROOF] flag?** That's the system working — it's your proof-card backlog. If you can source the claim, add a card; if you can't, the claim shouldn't be made.
- **Log every published variant in the tracker within 48 hours.** This is non-negotiable discipline, because:

## The system has no memory — the tracker and the files ARE the memory

Claude Projects don't learn between sessions. When a hook wins or an insight drives recruiter contacts, that learning survives only if you capture it. The loop that closes this gap:

1. Log published content + results in the **Content Log** (48-hour rule)
2. Once a month, paste your top 3 wins and bottom 3 misses into the project: `learn: [rows]`
3. The AI returns recommendation cards citing the exact rows used
4. A human decides what to adopt — nothing changes automatically
5. Adopted changes get **written into the Knowledge Base / Proof Library files** and logged in the Monthly Review tab. Editing the files is how the system remembers.

## What you gave up by not building the app (and when to revisit)

- **Multi-user review queues and approvals** → for now, that's you reading the draft. Revisit at 3+ people in the pipeline.
- **Claims/proof database with expiry** → the Proof Library IS this, in document form. Review expiry dates in the monthly loop.
- **Performance dashboard** → the tracker + monthly `learn:` loop covers it at this scale.
- **Persistent memory / version history** → the file-editing loop above, plus chat history. This is the one gap that never fully closes without the app — a conscious trade-off, accepted.

If Hire'in grows to a content team of 5+ with compliance sign-offs, the original 7-work-order package becomes worth building — and every one of these files drops straight in as seed data and the prompt layer. By then, 60+ days of tracker data will tell you exactly what the app must do.
